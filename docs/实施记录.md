当前已完成开发环境落地和 P1 核心流程的合成样本验证，并实现部分 P2/P3 基础。P0 已验证两份真实医院 PDF 的 OCR 与对应版式；更多独立样本、支付宝真机入口仍未验收，完整产品方案没有全部完成。

## 已实现

- React Native + TypeScript + Expo Router，两端本地原生编译。
- PDFKit / PDFium 读取文字；无可用文字层时以 iOS Vision / Android 内置 ML Kit 中文模型进行本地 OCR。纯 TypeScript 解析浙一余杭血常规单表、双表，未知布局仍保留原件。
- 原件最多 20 MB / 50 页，单页最多 2 万字符、整份最多 10 万字符，提取循环设 120 秒工作预算，页面渲染长边至多 3200 像素。此预算不能中断底层 PDF 库单次阻塞调用，不是硬超时承诺。
- 本地持久任务、SHA-256 精确去重、串行导入、失败重试、未知文件归档和删除。
- SQLCipher + 系统密钥存储；所有数据库读写串行执行，核对、修正历史、删除及就诊关联使用事务。SQLite schema v2，缺失密钥时保留原文件并报错。
- 核对和修正；患者冲突检查；未确认、无日期、不等式、未知映射不进入数值趋势。不同患者、单位、标本、方法分别分组。
- 就诊时间线、就诊编辑和报告关联；PDF 原件按页查看与系统分享导出。
- 固定白名单事件、默认关闭的统计同意、限长队列、重试及撤回；本地 HTTP 接收端和受保护的 JSON 统计接口。

## 孤立数字 0 漏读修复

“有核红细胞百分比”结果留空的原因是两端整页 OCR 均未检出原件中单独的 `0`，不是 JavaScript 把零当作空值。导入和重新识别现会定位已适配模板中缺失的结果格，只对这些格做本地补读。区域放大后仍无文字时，将原始字形置于白底并调整尺寸重试；不添加字符、不按参考范围猜值。真正空白或重试失败仍留空，补读结果带核对提示。

- 每份文件最多补读 12 格，另设 30 秒循环预算；底层单次 OCR 调用不能由此强制中断。已有非空结果不被补读替换，规则版本升为 v3。
- iOS / Android 原生测试覆盖 `0`、`9.9` 和空白格，并额外检查 App 自动定位的实际区域。曾发现手选区域与自动区域仅有微小边距差异就影响孤立字符检测；最终两种区域均通过，不能仅凭手选裁剪结果验收。
- 两端 App 均已重新编译、安装。真实报告页面测试重新识别后提取 22 项，最后一项输入框 `value-21` 显示 `0`。测试保留未保存候选，真实病历仍由用户核对确认。
- 使用实际自动区域的原生输出补入整页结果后，两份样本在两端各 45/45 项完整字段匹配，无新增差异。此结论仍仅适用于参与适配的两份样本。
- 类型检查、ESLint、59 个 Jest 用例和 HTTP 集成测试通过；覆盖零值显示和保存、缺值补读、失败保留空值、已有零值不重复识别。

## 真机启动时的 Worklets 缓存问题 · 2026-10-22

- 真机连接原来的 8081 服务后出现 `Failed to create a worklet`。该服务在安装手势依赖之前就已启动，沿用了旧 Babel 配置。实际返回的 `initializers.ts` 中，初始化自检函数只有 `worklet` 指令，没有转换后的 `__workletHash`；无需通过修改业务手势代码绕过自检。
- 已停止旧 8081 进程，以 `npm start -- --clear --host lan --port 8081` 重新启动。重新提取同一模块，确认自检函数已带 `__workletHash` 和插件版本 `0.5.1`。局域网的 `/status` 也正常返回，已将连接的 iPhone 重新指向此服务。真机运行时只读检查确认 Worklets 已初始化、React 根节点已挂载，首页的 `import-pdf`、`tab-records`、`tab-metrics`、`tab-settings` 控件均存在；没有导入或确认病历。两次编译输出保存在忽略目录 `tmp/worklets/`。
