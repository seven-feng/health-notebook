# 整份报告删除 · 交互方案

状态：2026-10-25 用户确认后已接入 React Native App，完整自动检查通过；iPhone 开发运行时已加载新模块。原型与原生验证分列如下。

预览：http://127.0.0.1:4173/?delete=1

## 问题与入口

修改前 App 只在原件没有任何检验分区或病历时显示“删除原件”，用户要先逐条删除才能移除整份 PDF；原件预览也缺少管理入口。

新方案在整份报告页面底部始终提供低强调的红色“删除整份报告”，与内容区分开。原件预览顶部增加“管理报告”，返回该原件的整份资料页。分区详情保持现有阅读布局，不另加一排文件操作。

## 删除前确认

沿用底部弹层：标题“删除整份报告？”，展示文件名、当前档案，以及本次实际涉及的数量。示例为 1 份 PDF、2 份检验记录、24 项结果；数字不是固定文案，正式实现需从数据库实时获取。

解释对应指标历史将移除；若有关联的独立就诊记录，明确说明“就诊记录保留，仅解除关联”。底部说明“仅删除本 App 中的资料，删除后无法恢复”。取消在左，红色“确认删除”在右，初始焦点落在取消；点遮罩或收起弹层也只取消。

确认后返回当前成员的记录列表，更新数量并提示“已删除整份报告”。不提供目前尚未实现的撤销／回收站承诺。

## 删除范围

| 对象 | 处理 |
| --- | --- |
| 当前成员这份 PDF 的本地副本、预览 | 删除 |
| 由该 PDF 生成的检验分区、结果和相关修订 | 删除，对应历史点移除；其他日期结果保留 |
| 以该 PDF 为原件的就诊记录 | 一并删除，并在确认中单列病历数量 |
| 仅关联这些检验、原件来自其他文件的就诊记录 | 保留，只解除被删检验的关联 |
| 被删就诊关联的其他文件检验报告 | 保留，只解除被删就诊的关联 |
| 其他成员的独立副本、相册原图、外部已导出文件 | 不处理 |

没有结构化记录时，确认只显示原件；有混合病历与检验时，按实际内容显示两类数量，页面可称“整份资料”。单独删除某个检验分区仍沿用原有独立入口，不隐式升级为整份删除。

## 原生实现约束

数据库中重新校验成员、文档归属及删除范围，在一个事务内移除结构化记录、关系并登记文件清理任务。复用现有持久清理重试机制，不逐条调用单记录删除产生半完成状态。删除操作进行中禁止重复确认；清理文件失败时区分“记录已移除、文件稍后清理”和“删除失败”，不能统一提示后让用户猜测。

解析／重识别仍在进行时应阻止新的写入；删除后的迟到回调不得重建文档或记录。若确认前数据范围发生变化，重新展示删除范围。原生实施需覆盖事务回滚、成员隔离、混合资料、独立就诊保留、其他文件报告保留、空文档和文件清理失败。
