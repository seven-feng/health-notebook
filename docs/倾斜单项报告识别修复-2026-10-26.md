# 倾斜、底部未拍全的单项报告

## 复现

本次读取的是手机最新导入的单项报告，和前一次验证的单项报告不是同一原件。使用手机原生 OCR 重新读取该 PDF：文字、结果、单位、参考范围均可读，但最终没有生成检验项目。

原因有两层：照片倾斜使原本同一行的表头和结果分落在不同水平线上；原先的短表规则还要求有效采集日期，而照片裁掉了采集时间，只保留了页眉的无标签日期。单独修正布局仍会被日期条件拒绝。

## 修改范围

- 通用表格按原布局解析失败后，才尝试根据连续汉字的共同倾斜方向对齐 OCR 坐标。需要足够字符、跨列分布和一致方向，只支持小角度倾斜。没有修改或旋转原件，也没有猜测缺失文字。
- 解析用的坐标与原件坐标分开。输出的原文区域、结果区域会映射回原图；过高的结果区域不提交给局部 OCR。
- 一至两项的报告仍要求完整表头、真实结果与参考范围、报告标题和姓名。清晰有效且独立的页眉日期可作为报告身份的辅助证据；出生、打印等其他日期不会满足此条件。
- 无标签日期不自动当作采集日期。采集时间未识别时保留空日期及核对提示。没有放开无身份信息的碎片、参考值表或科普示例。
- 元数据优先使用原生文字行；没有原生行时保留列间分隔，防止姓名与同排日期串在一起。

这是通用解析规则调整，未按医院名称、项目名称或某个具体数值硬编码；未添加云端 API，也未修改原生 OCR 模块。

## 验证

- `npm run verify`：类型检查、lint、39 套／527 项 Jest 和统计服务 HTTP 测试通过。
- 合成测试覆盖左右倾斜、相邻两项、数值零、原图坐标、缺失身份与结果、无效或无关日期、科普示例。
- 20 份历史 OCR 缓存共 327 项结果，用修改前后解析器比较，完整结果一致。这是缓存回归，并非重新对全部历史 PDF 执行 OCR。
- 在用户 iPhone 当前开发版中，通过报告页现有“重新识别原报告”操作重新运行原生 OCR 和解析，核对页实际出现一项，名称、数值、单位、范围与原图一致，原来的空结果提示消失；采集日期留空。
- 前后读取持久报告、原件和就诊记录，内容一致。新候选未替用户确认保存；调试临时状态已清理。

本次没有重装原生包或替换 Release 包，也未专项验收 Android 原生 OCR。调试原件和结果只存于本机忽略目录 `tmp/sideways-lab-photo-20261026/`，自动测试不包含患者资料。
