# 体检指标与历史趋势

日期：2026-10-26。用户已授权先出方案并实施。状态：已实现，完整自动检查及物理 iPhone 既有数据／页面运行时检查通过。

## 问题与目标

体检分区能提取和核对，但通用解析器没有建立指标对应关系；旧趋势函数要求指标代码、单位、标本、方法全部存在，导致整份体检的已确认结果被跳过。已有两个不同日期的低密度脂蛋白结果，指标页却只显示一次。结果并未丢失。

所有已核对结果都应在指标页可查。明确匹配的项目进入同一历次对照；无法比较的结果仍有名称、原数值、单位、日期、各次参考范围、来源报告及原因。草稿不混入已确认结果。

## 本轮产品行为

保持现有列表、参考范围筛选和点击展开。匹配后的体检结果直接进入对应指标，不要求重新导入、重新 OCR 或再次确认。每个历史结果保留自己的日期与参考区间；点击返回原报告。原名称和原单位在历史行保留，别名和等价单位只用于展示层归并。

名称或单位未适配的精确数值独立展示，解释不能合并的原因；同一指标遇到明确不同的标本、方法、单位也分开，展示区分信息。报告没注明方法或具体标本时，允许在有明确常规检验类别证据的同类项目中作数值对照，同时提示未注明，不把它解释为检测条件一致；这些结果不与已明确的其他条件自动混合。

非数值、带“<／>”限定符、日期或姓名缺失、仍有核对疑点的结果，汇总到“暂未进入趋势”列表，点击可查看每条结果与具体原因，跳回来源报告。页顶始终显示数量，不默默消失；没有曲线也能查看这些结果。此类不强行计算差值或异常状态。

## 匹配与数据约束

- 归属仍以成员 ID 隔离；患者姓名仍需要已核对，不能跨成员合并。
- 使用本地、可审查的常见血常规／生化／一般体检白名单。仅匹配明确同义名称，不使用模糊匹配、LLM 或数值大小推断。空腹血糖与未注明空腹的葡萄糖分开，细胞百分比与绝对计数分开，普通与超敏 CRP 分开。
- 通用报告需要类别证据：血常规标题、一般检查标题或实验室／生化标题加多项独立生化指标。未知用途、尿液等冲突上下文不套血液匹配；手动无背景记录仍单独展示。
- 单位仅做等价字形处理，如 `umol/L`、`μmol/L`，`10⁹/L`、`10^9/L`。不自动换算质量／摩尔浓度，不根据医学常识补 OCR 错位的单位。明确无量纲的比值／BMI 可无单位，其余缺单位的记录单独展示。
- 显式标本和检测方法按实际信息分组；缺失信息保留“未注明”，不能充当通配符把冲突方法连接起来。原报告没注明的字段不回写成推测值。
- 同日多个来源都保留，不暗中去重、不推断先后、不计算当日差值。同一报告同一结果不因重复输入计算两次。

新增一层纯函数生成指标视图与未进入趋势的原因，不改数据库 schema、不覆写报告、原始数值、人工修改和修订。每次从现有结构化数据计算，因此旧资料立即生效，编辑／删除／切换成员也会即时更新。

## 验证

使用合成数据覆盖别名与单位、体检和既有浙一记录合并、原参考范围保留、未知或冲突条件隔离、不同成员、同日多结果、限定符／定性／缺日期、人工修改后重新分组、重复来源去重、非空待处理列表。回归现有指标、报告和成员测试，完整运行类型检查、lint、Jest 与统计服务测试。

真机只读比较已有数据：低密度脂蛋白历史应包含原先两次结果，全部已确认观测均能在趋势或原因列表中找到；确认手机加载新模块、展开历史和来源跳转。不会为验收修改患者数据。


## 实现记录

- `src/domain/metric-matching.ts`：明确别名、等价字形、报告类别证据、未注明／已注明条件的分组。范围包含常见血常规与生化、身高／体重／BMI／血压；肿瘤标志物、eGFR 方程、呼气试验等未新增通用跨报告匹配。
- `src/domain/metrics.ts`：纯函数生成趋势与未计入原因；未知项目精确数值单独展示；按来源去重，保留同日不同来源。已有代码仍可沿用原严格匹配，但旧浙一代码不得绕过新白名单的单位或类别冲突校验。
- `MetricsOverview` 与 `MetricTrend`：保留已有外观，展开时显示条件说明、原名称／单位及来源；历史点按报告与结果共同标识。
- `UntrendedResults` 与指标页：顶部数量入口，原值／参考范围／日期／原因列表与来源跳转。现有缺日期补录入口保留。

上述处理不调用 OCR、不新增网络请求、不写报告数据；更新后从同一份数据库即时计算，编辑／删除与成员切换沿用现有刷新机制。
