## 用户流程

- 多页 PDF 在时间线上只占一个文件入口。打开后列出检查分区、结果数量、待核对数量和完整原件。
- 每个分区沿用现有核对列表。跨页检查保留每项实际页码和表头来源，核对图片仍按实际页分组。
- 阴性、等级和其他文字保留为文本；限定数值保留运算符。均不擅自转换为数字或加入趋势；通用项目仍需满足既有代码／单位／标本／方法／日期规则才能比较。
- 未整理内容可按页查看或手动补录。覆盖信息是保守的区域记录，提取表格不表示整页已识别。
- 暂存和保存后直接读取 SQLite 中的结构化结果，不重新读取 PDF。
- 删除最后一个多页检查分区会保留原件。分区清空后，用户可以单独确认删除原件。

## 原记录与重新识别

单个分区重新识别时，重新建立整份文档上下文，再按分区标识定位。新结果保存前不会修改旧记录。明确保存使用既有事务和修订历史；取消、提取失败或保存失败均保留旧记录及就诊关联。

旧记录若一页对应多个分区，或新分区跨越其他旧记录，不自动合并覆盖。可从整份报告选择“重新整理整份报告”，预览分区列表后明确选择“另存这些新分区”。这会保留全部旧记录、修正和就诊关联，也可能产生重复分区；界面会事先说明。第一轮未提供复杂的旧记录合并／迁移向导。

数据库升到 `user_version=4`，只增加 JSON 可选字段，不清空旧内容。旧版最大支持 3，因此会拒绝打开新数据库。回退程序不能直接配合升级后的数据库使用；需要恢复升级前的完整备份。已验证旧数据迁移、事务失败回滚、原件保留和成员隔离。

上表来源页匹配不等于所有裁剪框都经过像素级人工标注。原件预览已通过实际 App 检查，完整坐标区域的逐像素基准仍可继续补充。

iOS 使用实际 PDFKit 提取输出，Android 使用 `ComplexDocumentTest` 调用实际 PDFium 提取器。两端均读取 40 页文字层。一次模拟器原生提取分别约 172 ms 和 1,743 ms；最近一轮 Mac 上 TypeScript 解析分别约 325 ms 和 929 ms，后台编译／模拟器并行时会有波动。这些是不同实现输出的本机测量，**不是手机 Release 耗时或内存承诺**。

原两份浙一血常规两端各 45 项完整字段回归通过。9 个公开样例的比较结果与此前基线完全一致，包括已知错漏，没有把原有错误重新计成正确；其中已包含双栏生化样例。另对原有 32 项浙一生化样本复用已保存的 macOS PDFKit 输出，与修改前逐字段比较完全一致，金标仍为 31/32 项完整匹配；这不是新一轮 iOS／Android 生化原生验收。不能把公开样例的数值对比称为全字段验证。
