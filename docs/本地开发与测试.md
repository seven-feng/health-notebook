# 本地开发与测试

更新：2026-10-25。日常开发默认使用 **Debug**；需要脱离电脑体验时再明确采用 Release。本文是操作说明，不表示当前电脑服务、模拟器或手机安装模式已被自动检查。

## 1. 日常改页面和规则

```sh
cd /Users/fanqie/Documents/doctor
nvm use
npm start
```

`nvm use` 读取 `.nvmrc`，切到项目已验证的 Node 22.22.0。`npm start` 启动 Metro 开发服务，为已安装的 Development Build 提供 JS；不是编译或安装 App。

终端按 `i` 打开 iOS 模拟器，按 `a` 打开 Android。多台模拟器时按 `Shift+i` 选择对应已安装开发包的设备。普通 TypeScript、页面、规则和样式修改通常通过开发服务加载。

已安装 Debug 的 iPhone 也可直接加载这些改动，无需先打开模拟器或重新安装。若手机锁屏、断网或修改时未连接 Metro，重新打开 App 后可能仍看到旧页面：先保存正在编辑的内容，确认连到本项目开发服务，再从手机开发菜单重新加载。该操作只刷新 JS，不卸载 App，也不更新原生模块。2026-10-24 的病历小数点解析、阅读布局和体格检查排版均属 JS 改动。

停止服务：在启动 `npm start` 的那个终端按 `Ctrl+C`。关闭模拟器窗口不等于关闭 Metro。若 8081 已占用，先查已有项目服务，能复用就复用，不要不断开新服务或直接结束所有 Node 进程：

```sh
lsof -nP -iTCP:8081 -sTCP:LISTEN
```

确需清理缓存时，先结束原 Metro，再启动：

```sh
npm start -- --clear
```

## 2. 首次安装与原生变更

```sh
npm ci
npm run check:env
npm run ios -- --configuration Debug
```

Android 单独运行：

```sh
npm run android -- --variant debug
```

Swift／Kotlin、原生依赖、权限或系统文件接收配置变更需要重编译安装；仅刷新 JS 不会更新 OCR 或文件接收模块。项目有自定义原生模块与 SQLCipher，不能用 Expo Go 替代 Development Build。

区分原生 OCR 引擎和 TypeScript 解析规则：前者修改后需要构建，后者在 Debug 加载新 JS 即可。解析修复也不等于历史数据自动重识别；体格检查的显示排版则会直接应用于已有记录。

脚本在可用磁盘不足 12 GB 时停止，建议至少预留 15 GB。按需构建一个目标，避免同时编译多个平台、同时运行多个模拟器。尤其同一 `ios/Pods` 工程的不同配置构建要顺序执行，依赖脚本可能切换共享的预编译头文件。

`app.config.ts` 和 `plugins/` 是系统配置来源；更新这些配置后用 `npx expo prebuild` 同步，再构建。不要把业务配置只改在生成工程。已有 Xcode 签名／Scheme 设置需要保留并核查，不应为了普通代码修改重新创建工程或无故清理原生目录。

## 3. iPhone 真机 Debug

1. 连接、解锁并信任电脑，按系统要求启用开发者模式。
2. 打开已有工作区 `ios/app.xcworkspace`，不新建项目。在 App target 的 Signing & Capabilities 中使用现有开发团队与应用标识。
3. 选中该 iPhone，在 Product → Scheme → Edit Scheme → Run → Info 中选择 **Debug**，再点 ▶ 构建并安装运行。
4. 保持 Metro 可访问，手机与电脑网络互通，并允许 App 使用本地网络。首次可能进入开发启动页，需要选择对应的开发服务。

也可由 CLI 选择设备并明确使用 Debug：

```sh
npm run ios -- --device --configuration Debug
```

更改 Scheme 配置不会自动改变已安装的手机 App。只有重新构建并安装，手机才切换到那次构建的模式。之前装过 Release、之后运行 Debug 都是可能的，不能用历史日志直接判断当前手机状态。

覆盖安装应保留同一应用的数据；**不要通过卸载来切换构建模式**。当前数据库 schema 为 6，旧版业务代码可能不兼容，即使它也是 Debug。回退需考虑代码与数据版本，而不只是 Scheme。

## 4. 脱离电脑的体验版本

需要独立体验时，在 Xcode 把 Run 配置设为 Release，再构建安装；或明确执行：

```sh
npm run ios -- --device --configuration Release
```

Release 内置 JS，核心流程不依赖 Metro。仍需要检查本地离线流程和签名有效期；安装到手机不等于 App Store／Google Play 发布。测试后继续开发时，再明确构建安装 Debug。

安装记录至少包含：构建时间、源码范围、目标设备、Debug／Release、是否启动成功、实际验证的功能。不要因为切了选项就写“手机已切换”，也不要因为进程存活就写“全部真机验收通过”。

## 5. 把报告放进模拟器

PDF 可以拖入模拟器，但系统默认打开方式不一定把文件保存在“文件”App。需要在系统界面保存到可由文件选择器访问的位置，再从 App 导入；仅在浏览器预览不等于已保存。

实际微信／支付宝交接、相机拍摄及权限体验用真机验证。iOS 模拟器适合文件、相册和 UI 流程，不能代替真机相机或第三方 App 测试。

自动化使用专用测试模拟器和合成资料。不要把 E2E 指向正在整理真实报告的设备；相关脚本会重启测试 App，并可能确认、修改合成记录。

## 6. 常用验证命令

轻量验证：

```sh
npm run verify
```

执行 TypeScript、lint、Jest 和统计服务 HTTP 测试，不启动模拟器。纯文档整理只需检查内容、链接和证据，不必重跑原生编译。

两端 JS 与资源能否导出：

```sh
npm run check:bundles
```

它不构建 IPA／APK，不证明手机安装或 Release 完整流程通过。

在已启动的专用模拟器、已安装 Debug 包及 Metro 环境中，按本次改动选择流程：

```sh
npm run e2e:ios
npm run e2e:android
npm run e2e:ios -- .maestro/sections.yaml
npm run e2e:android -- .maestro/sections.yaml
npm run e2e:ios -- .maestro/family-records.yaml
npm run e2e:ios -- .maestro/reparse.yaml
npm run e2e:ios -- .maestro/compact-review.yaml
npm run e2e:ios -- .maestro/source-preview.yaml
npm run e2e:ios -- .maestro/photo-import.yaml
npm run e2e:ios -- .maestro/edit.yaml
npm run e2e:ios -- .maestro/unsupported.yaml
```

已有同名 Android 流程可将脚本名改为 `e2e:android`。照片流程和部分回归需要预先准备对应测试资料，具体见[图片测试](图片导入测试.md)与各 YAML。多设备时指定 `DOCTOR_TEST_DEVICE`（iOS UDID／Android serial）。Maestro 优先使用 `.local/tools/maestro/bin/maestro`，否则读取 PATH；测试输出在 `test-results/`。

`core.yaml`、`unsupported.yaml`、`sections.yaml` 的脚本会向模拟器收件目录放入合成 PDF。这验证了后续导入链路，**不替代外部应用的 URL／Intent 交接测试**。缩放、双指和拖动另按[原图手势测试](原图手势测试.md)验证。

原生 OCR 与样本比较：

- iOS：`scripts/prepare-ios-ocr-tests.rb` 生成 XCTest 工程；本机 CocoaPods 自带 Ruby 的用法见[多版式测试](多版式OCR测试.md)。指定实际测试模拟器，只运行所需类。
- Android：使用本地 JDK 17，在 `android/` 运行模块 instrumentation 测试；样本仅进入测试 APK，流程见同一记录。
- 已有脚本：`check-private-ocr.mjs`、`check-public-ocr.mjs`、`check-document-parser.mjs`。各脚本退出码含义不同：公开样例比较执行成功不等于全字段正确；复杂文档金标当前因 4 个图形箭头缺失返回失败。

真实资料与完整输出放在忽略的 `private-fixtures/`、`tmp/`；合成 PDF 在 `assets/samples/`，生产页面不引用这些测试文件。首次引导中的合成效果截图属于展示素材，不会生成用户记录。

就诊相关改动可先做定向回归：

```sh
npm test -- tests/parser/visit.test.ts tests/domain/visit-text.test.ts tests/components/visit.test.tsx tests/components/visit-members.test.tsx
```

这些测试分别覆盖病历段落／小数点、展示排版、阅读与编辑保存、成员切换后刷新。它们不替代手机上长正文与大字号、原件来源页、双指缩放、备注键盘以及弹层打开／关闭的实际检查。真机验收中要区分“模块加载”“运行时数据检查”和“页面视觉／手势确认”。

## 7. 可选统计的本地调试

正常本地整理无需启动统计服务。确需验证统计时，在独立终端运行开发接收端：

```sh
ANALYTICS_ADMIN_TOKEN=local-development-token-only npm run analytics:dev
```

只监听 `127.0.0.1:4318`。按 `.env.example` 设置 `EXPO_PUBLIC_ANALYTICS_URL` 为 iOS 模拟器的 `http://127.0.0.1:4318` 或 Android 模拟器的 `http://10.0.2.2:4318`，重启 Metro，再由设置页主动开启统计。开发令牌仅用于本机测试，不能当作生产密钥；管理员令牌不可写入 `EXPO_PUBLIC_` 变量。

```sh
export ANALYTICS_ADMIN_TOKEN=local-development-token-only
curl -H "Authorization: Bearer $ANALYTICS_ADMIN_TOKEN" http://127.0.0.1:4318/stats
```

正式统计尚未部署，Release 只接受 HTTPS 配置；不要把测试端启动当作线上用户监控已经可用。

## 8. 结束测试与降低负载

完成测试后停止自己启动的 Metro／测试命令，关闭专用模拟器。编译已结束后风扇可能仍需散热，先检查正在运行的进程，不靠风扇声判断仍在构建。

iOS 可以用 Simulator 的 Device → Shut Down，或针对已确认的测试设备执行 `xcrun simctl shutdown <UDID>`；Android 关闭对应模拟器窗口。已有其他会话在用的服务和设备应先核查用途，不一概关闭。手机上的 Release 核心功能不依赖这些电脑进程。
