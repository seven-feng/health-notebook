# 超声报告原文识别 · 2026-10-27

## 原因与范围

用户提供的超声检查照片包含检查项目、临床诊断原文、检查所见和报告提示，结构不是检验指标表。系统 OCR 能读取主要打印文字，原解析入口没有此类段落规则，因而保留为未知资料。附件方向不是本次归因；本地为 OCR 对照旋转了一份副本，随后直接在 iPhone 已导入原件上重识别验证。

首批只支持有明确超声报告标题、唯一患者姓名及非空所见／提示的打印版式。缺少证据、存在身份冲突或示例说明时保持未知，不靠医学常识猜测内容。尚未支持其他影像种类、跨页正文合并和可靠手写整理，也不解读超声图像。

## 实现

- 统一 PDF／照片导入无需选择类型；`src/parser/ultrasound.ts` 优先识别超声页，命中后不交给表格解析。模板为 `ultrasound-text-v1`，文档解析版本为 4。
- 使用 `Report.reportType: 'imaging'`，复用原报告存储、成员隔离、修订、重识别、删除和原件预览，不改数据库 schema 或原生模块。
- 段落保存 `resultKind: 'text'`、OCR 原文 `originalValue` 和来源矩形。展开可修改标题和多行正文；无单位／参考范围编辑框，也无数值范围条。
- 默认全文展示；照片文字提醒对照小数、尺寸和分级。明显偏离正文左侧对齐的旁行不拼接进正文，但保留在来源区域，并要求核对。该规则只是版式启发式，不是手写检测器，缩进排版仍可能遗漏。
- 日期优先明确检查时间，否则使用报告时间并标明来源。不借用出生、打印或手写日期；无效和冲突日期留空。
- `buildMetricData` 和缺日期趋势提示排除 imaging，包括文字历史；尺寸、分级不会自动生成指标。
- 首页改为“就诊记录／检查报告”，超声显示“段文字”。未识别原件增加重新识别资料入口，仍沿用整份资料页。
- 单份重识别保留 ID 和成员，只生成候选；整份重识别候选保存时更新文档分类，采用既有另存策略。旧资料不自动改写。

## 同日追加：正文准确性复核与优化

用户逐字对照后指出正文仍有错误。前一轮验证证明段落能够提取，不能代表正文完全准确。本轮确认并修复三项代码问题：

1. 旁注规则原来用待判断行的高度放宽缩进限制，较大的手写框反而可能通过。改为依照段落标题确定并限制容差，旁注仍在原图裁切范围内，并继续提醒核对；这不是通用手写分类。
2. `src/parser/ultrasound-text.ts` 只连接几何上相邻、前行接近段落右边缘的折行，避免“结节”“血流信号”被拆开。句末、编号、新段间距和短行保留换行。
3. 数字断行不会直接拼成一个大数。仅在其他 OCR 结果的行末确实有小数点、两侧坐标匹配、整数与小数部分均有对应且所有读数无数字冲突时恢复；无证据或冲突保留断行。直接识别到的行末小数点可正常续接。恢复后仍需核对，`originalValue` 保留恢复和重排前的 OCR 文字。

完整 `npm run verify`：42 套／565 项 Jest、TypeScript、ESLint、1 项统计 HTTP 测试通过。新增 14 项覆盖大手写框、连续中文、编号与段落保留、小数证据、不同位置与冲突、文字 PDF 不补点、无数字猜测、跨行单位不清的显式提示和不按词典替换医学词汇。

使用原附件的本地 OCR 输出重新解析，原先混入的手写数字已排除，“结节”“血流信号”正常连接，跨行尺寸末尾恢复为 `0.25cm`，原读数与核对警告保留。额外用同一原生 OCR 在临时程序中开启语言纠错进行对照，“虫部”“天小”仍未改善，未将该参数改动加入 App，也没有硬编码替换词语。字符错误仍是本轮明确保留的限制。

本轮局部代码与证据位于 `/tmp/doctor-ultrasound-text-20261027/`；真实内容仍不写入合成测试。iPhone 已重新启动并加载新版，沿用报告页的重识别入口生成候选。运行时验证“结节”“血流信号”不再被断开、手写数字排除，`originalValue` 与整理后正文分开保留，成员和已存报告／文档均不变，无运行报错。候选停留在手机核对页，未保存或确认。

必须区分附件与手机原件：聊天附件的 OCR 有足够证据恢复 `0.25cm`；手机本次 OCR 在同一尺寸附近读成 `0.\n250m`，同时存在符号、单位及中文错字。证据不足时不会把 `250m` 猜改为 `25cm`，已经保留断行并新增“跨行数字的单位或接续关系未识别清楚”提示。因此本轮证明了排版和旁注改善及小数恢复规则，没有证明所有平台、每次识别都能自动还原该数值。Android 真机与原生视觉验收尚未进行。
