# 门诊病历与双分类首页 · 首版实施

2026-10-23。对应用户确认的 `prototypes/family-records/?visit=1` 方案，现已接入 React Native App。浏览器原型与原生验收分别记录。

## 用户流程

- 首页保留成员选择、资料库、PDF／拍照／相册入口；资料库显示就诊次数和检验份数。
- 首页只有“就诊记录／检验报告”，每个成员独立记住选择。只有检验且未选过视图时默认显示检验。关联检验不会从检验视图消失。
- 导入先持久保存原件，再在本机识别类型。有明确标题的打印病历进入就诊核对，检验进入既有指标核对；多页文件打开整份资料；不确定类型进入手动选择。
- 就诊核对重点展示就诊原因、医生诊断原文、处理／医嘱原文，次要段落折叠。字段可直接编辑，原文可在当前页打开并手势放大；保存按钮固定在底部，不要求逐段勾选。
- 日期来自明确标注的就诊时间，不使用导入时间、生日或打印时间。缺日期可暂存；姓名不匹配须确认，不能静默切换成员。
- 保留手动就诊、个人备注、同成员检验关联和双向详情入口。既有无法读取指标的报告也可“按就诊病历整理”，另建病历时明确保留原检验记录。

## 实现与数据

- iOS Vision 和 Android ML Kit 返回 `readingLines`，保留原始行顺序和区域；iOS PDFKit 文字页也返回行结构。已有检验用字符、辅助数字、另一尺度结果不变。Android 文字页使用既有位置拼行。
- `src/parser/visit.ts` 识别标题，处理“主／诉”等被 OCR 拆开的标题；`src/parser/records.ts` 负责页面分类与分流。首版段落规则版本为 1，检验文档解析版本仍为 2。
- `Visit.original` 保存原始 OCR 行与段落区域；`sections` 保存人工编辑值。后续保存不会覆盖已存原文。打开历史记录不重复 OCR。
- schema 6 为 `visits` 增加原件外键 `document_id`。旧手动就诊兼容；病历原件不需要挂在伪检验报告下。导入病历、报告与文档状态一起事务提交。
- 归属检查同时覆盖原件、成员姓名和关联检验。删除病历保留关联检验；仍被病历或报告使用的原件不能删除。独占单页原件可随记录删除，多页文件保留至明确删除。文件清理沿用持久化重试任务。

## 仍需验证的范围

- 多医院、低清、倾斜及不同标题的独立样本；目前真实病历只有一份开发照片。
- 原件片段在真机的完整核对体验、手机相机／相册和外部 PDF 的实际交接、离线及性能。
- 一张照片按一份病历处理；多页病历不自动续接或按日期合并。独立页的候选分别保存。续页、无标题段落及手写资料保留原件供手动整理。
- 同一页同时含病历正文和检验表格时优先病历；表格需要从原页补录，不承诺两类同时完整提取。
- 没有增加 LLM、云 OCR、处方推断、复诊日期推算或病情结论。病历主动重新识别候选仍未提供。
