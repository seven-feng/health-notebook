# 同一份体检报告统一填写姓名

日期：2026-10-26。

问题：多页 PDF 按血常规、尿常规等类别整理后，姓名未能提取时，用户要逐类输入。新增“统一填写姓名”，在整份报告页和多页报告核对页的姓名下方使用同一组件。

## 交互

- 有待核对检查缺姓名时显示入口；页内展开输入框、取消和“填写 N 类检查”按钮。
- 优先采用当前核对页输入的姓名，其次采用同一原件唯一的已有姓名，最后参考成员姓名；只是输入建议，用户点击填写才保存。
- 只补本报告中待核对检查的空白姓名。已有姓名保留，存在冲突时不批量修改，提示逐类核对。
- 填写完成会显示数量；不会把指标标为已核对，不会代替原有成员归属确认，也不保存核对页中其他未提交的修改。
- 已确认、已归档、其他文件及其他成员的记录均不参与；识别后的未保存候选沿用既有另存流程，当前批量操作只针对已入库记录。

## 实现与验证

`src/components/DocumentPatientFill.tsx` 负责页内交互；`src/db/index.ts` 的 `fillDocumentPatient` 在一次事务内重读归属、姓名和状态，只更新元数据并留下修订历史。失败时整批回滚，重复点击不会重复写入。

回归覆盖只补空白、保留 0 数值及待核对状态、原件与就诊关联不变、其他原件隔离、归属校验、姓名冲突、事务回滚、修订历史、身份核对仍有效、取消不保存、重复提交防重，以及核对页数字修改／手填姓名不被覆盖。

完整 `npm run verify` 通过：36 套／386 项 Jest、类型检查、lint 和 1 项统计 HTTP 测试。日志 `tmp/document-patient-20261026/verify.log`；指标页既有图标异步加载仍输出 `act` 测试警告，该套及本次新增测试均通过。

iPhone Debug 已加载新模块，在实际缺 5 类姓名的整份报告页检查了“统一填写姓名”入口、页内输入／提交按钮及取消。取消后报告、文档、就诊的运行时数据均与打开前一致；没有替用户提交姓名，没有原生重新编译。证据保留在同目录 `phone-after.json`、`form-check.json`、`cancel-check.json`。真实姓名写入以自动数据库回归为证；本轮未执行用户资料写入、Android 真机、键盘／大字号截图验收。
