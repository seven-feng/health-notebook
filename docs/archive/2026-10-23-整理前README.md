# 我的健康记录

React Native + TypeScript + Expo，本地保存自己和家人的就诊记录，支持 iOS、Android。

**当前是可运行的验证版：已经实现核心流程；还不是产品方案中完成全部验收的正式首版。** 已加入本地 OCR，并适配两份浙一余杭血常规的单表、双表样本。加入漏读单元格的局部识别后，两端原生输出的 45 项完整字段均与人工核对一致，包括此前漏读的单独数字 0。部分名称、单位和补读结果仍需逐项核对；不能据此宣称支持所有医院或全部浙一模板。

另已加入浙一余杭“肝肾脂糖电解质测定”双表的首份生化样本，iPhone 实测提取 32 项候选，其中一项末尾箭头仍被识别成数字，全部要求核对。这个新增模板不包含在上面的 45 项血常规匹配结果中。

2026-10-23 新增按表头定位的通用表格解析与不同尺寸的本地中文 OCR。9 张公开样例中，iOS 7 张、Android 6 张能整理部分或全部项目；仍有漏项、箭头/单位误读，不能视为完整准确识别。新格式先支持核对和保存，尚不自动加入跨医院趋势。详见[多版式 OCR 测试与限制](../多版式OCR测试.md)。此更新需重新编译原生安装包。

## 现在能体验什么

- 右上角切换“我”和家人的档案；报告、待核对项、就诊及指标各自独立。默认“我”，成员弹层添加家人，设置中编辑资料；旧数据自动保留在“我”。
- 导入到当前成员；姓名冲突只提醒核对，不自动换人。相同文件按成员去重；原有详情、核对与放大查看保持完整。

- 导入 PDF → 自动读取文字或本地 OCR → 自动填好核对页 → 修正、确认、保存。iOS 使用系统 Vision；Android 内置 ML Kit 中文模型，不上传报告，也不需要首次下载模型。
- 拍照识别或从相册选择 → 裁剪、旋转 → 开始识别 → 核对保存。一次一张，全程在本机识别和保存；相册原图不变。照片识别后统一确认保存，仅具体疑点需逐项核对；支持原图放大查看，导出为 PDF。
- 已适配的浙一报告支持裁掉底部空白后的截图。实测一张双栏血常规截图，两端提取 23 项且数值与原图一致；部分名称、单位和箭头仍需核对，截图缺失的采样日期不会自动推断。倾斜、遮挡的未知体检表仍不支持自动整理。
- 已导入的报告可点“重新识别原报告”。候选结果保存前不覆盖旧记录，可放弃；保存后保留修订历史和就诊关联。
- 可疑数值、箭头、名称或单位建议逐项标出；未核对项不进入趋势，漏读数字不自动填 0。
- 已核对报告以连续列表展示指标、数值及参考范围横条，标明数值在范围内、低于或高于参考范围。仅对确定的数值和有效双侧参考区间绘图；待核对、定性结果、单侧或缺失范围保留原文。点击项目仍可展开原件和编辑，参考范围位置不代表诊断结论。
- 核对页按原报告顺序每组最多展示 5 项，跨页或左右分栏时拆组；顶部只统计待核对的疑点。普通项目无需逐项或额外按组确认；本组疑点处理完后直接“下一组”，最后统一“保存报告”。翻组和收起不会解除疑点；修改结果会重新标记待核对，暂存保留已处理的状态，重新打开定位尚有疑点的组。
- 核对列表采用白底细分隔线，右侧圆圈可直接确认疑点，再点撤销；无需先展开卡片。点数值可展开修改，修改后需重新勾选。数值 `0` 可以确认，名称或结果为空时需先补全。见[勾选核对截图](../screenshots/inline-review.png)。
- 每组上方展示对应的原报告片段，点击可放大；单项展开后仍可查看对应行。大图支持双指缩放、放大后拖动和双击放大或恢复；关闭保留草稿。已有识别记录无需重新识别，没有可靠定位时提供查看整页入口。
- 清晰的 ↑／↓ 独立显示为“原报告标记：高于／低于参考范围”；仅被误读成数字或方向不确定时要求核对。已保存的旧结果需重新识别后使用新规则。
- 已适配模板的结果格漏读时，自动局部放大补读；只接受原件识别出的内容，空白格和识别失败仍留空。此修复包含原生模块更新，需要新版调试包。
- 已核对报告中的可比指标按日期显示变化，修改数值后同步更新差值。
- 就诊时间线、手动就诊记录及报告关联、PDF 原件按页查看和导出。
- 本地文件去重；中断后重试；未知模板归档；解析失败的文件可手动整理或删除。
- iOS 接收外部 PDF 后由原生模块清理自己的接收目录；只清理已有持久原件的接收副本，清理失败不会让成功导入显示为失败。此修复需要更新原生安装包。
- SQLCipher 数据库和系统密钥存储。重启后直接读已保存结果，不重新解析 PDF。
- 默认关闭的可选使用统计。尚未配置或部署任何统计接收地址。

## 在这台 Mac 运行

已安装好两端调试版。日常修改页面和 TypeScript 时，只需要启动 Metro：

```bash
cd /Users/fanqie/Documents/doctor
nvm use
npm start
```

在终端按 `i` 打开 iOS 模拟器中的 App，或按 `a` 打开 Android。如果提示未安装 development build，按 `Shift+i` 选择已经安装 App 的 iPhone 16 Pro / iOS 18.6，或在目标模拟器上先运行一次 `npm run ios`。也可在已安装的 App 开发启动页点本机服务。进入“记录”，点“导入 PDF 报告”选择自己的文件，核对保存后查看“指标”。也可从其他应用打开 PDF 并选择本 App。拍照和选图入口也在“记录”页；iOS 模拟器使用相册测试，真实拍摄用真机。

首次安装依赖，或改了原生代码、原生依赖和 App 配置时：

```bash
npm ci
npm run check:env
npm run ios
npm run android
```

两个平台的构建命令分别执行即可。文件接收、Swift/Kotlin、SQLCipher 配置变化需要重编译；普通页面修改会热更新。第一次下载原生依赖需要联网和足够磁盘空间；脚本会在空间不足 12 GB 时停止，建议留出 15 GB 以上。

手势查看原图新增 Gesture Handler / Reanimated 原生依赖。更新到这一版时需重新运行两端构建，并在原来的 Metro 终端按 `Ctrl+C`，再执行 `npm start -- --clear`，避免旧进程沿用未启用 worklets 的编译缓存。

本次图片导入新增 `expo-image-picker`、`expo-image-manipulator` 和原生图片转换方法，需要重新运行 `npm run ios` / `npm run android` 安装新版开发包。本机两端模拟器已更新；真机也需要重编译安装。

使用本地 Development Build，因为 PDF 和 SQLCipher 是原生模块；普通 Expo Go 无法运行本项目。

已验证工具链：Node 22.22.0、Expo 54.0.38、React Native 0.81.5、React 19.1.0、Xcode 16.4、CocoaPods 1.16.2、JDK 17、Android SDK 36 / NDK 27.1.12297006。构建脚本自动使用本机 Homebrew JDK 17，不改系统默认 Java。Android 的 SQLCipher 依赖另使用 NDK 27.0.12077973。

模拟器：iPhone 16 Pro（本次 OCR）、iPhone 16 / iOS 18.6；Pixel 3a / Android API 34 / arm64。

已经导入过的两份真实 PDF 无需删除重传：进入报告 → “重新识别原报告” → 核对候选字段 → 保存。更新原生代码后需要安装新调试包，仅热更新 JS 不会更新 OCR。App 已修复 iOS 更新后沙盒目录变动导致原件路径失效的问题。

E2E 依赖 `npm start`、已安装的调试包和已启动的专用测试模拟器（不要导入真实报告）。先跑核心流程，再跑修改、未知模板流程。核心和未知模板测试由脚本在模拟器内放入合成 PDF，再通过正常接收流程导入，不依赖 App 内的测试按钮。准备样本时会重启模拟器内的 App，不清空数据库；不支持向真机注入样本。Maestro 2.11.0 已放在本机 `.local/tools/maestro`；其他电脑从 [Maestro 官方发布页](https://github.com/mobile-dev-inc/Maestro/releases) 安装，脚本也支持 PATH 中的 Maestro。命令关闭 Maestro CLI 自身的使用统计。

Android 系统文件选择器也有单独测试（模拟器的文件应用使用英文界面）：

```bash

npm run e2e:android -- .maestro/android-picker.yaml
```

每端同时只启动一台测试模拟器，或设置 `DOCTOR_TEST_DEVICE` 指定 UDID / adb serial。日志、截图和 UI 层级保存在 `test-results/`，不会提交。共享模板里已处理两端开发启动页差异。

合成 PDF 在 `assets/samples/`，仅供测试脚本使用；App 页面和打包入口不引用这些文件，开发版和发布版都不显示测试入口。真实样本只放入被 Git 忽略的 `private-fixtures/`。调试版依赖 Metro，不能作为无网络 Release 验收的替代品。

## 代码入口

| 路径                     | 作用                                                                     |
| ------------------------ | ------------------------------------------------------------------------ |
| `app/`                   | 记录、指标、核对、原件、就诊、设置页面                                   |
| `src/domain/`            | 数据模型、十进制计算和可比性规则                                         |
| `src/parser/`            | 按文字及坐标解析已验证模板                                               |
| `src/db/`                | SQLCipher、迁移、串行事务及修正历史                                      |
| `src/services/import.ts` | 原件接收、去重、任务状态、重试和归档                                     |
| `modules/local-pdf/`     | PDF 文字提取、Vision / ML Kit 本地 OCR、图片转换、原件预览、外部文件接收 |
| `plugins/`               | 可再生成的系统配置                                                       |
| `services/analytics/`    | 可选本地统计接收端                                                       |

`ios/`、`android/` 是生成工程，不作为配置源。用 `npx expo prebuild` 更新原生配置，再运行对应构建命令。不要只在生成工程里改业务配置。

## 可选的 UV / PV 统计

当前未启用 App 自行采集的 UV/PV 统计。Android ML Kit 的 SDK 诊断活动需另行核查，见 [依赖记录](../third-party.md)。使用测试接收端时，在独立终端设置开发用访问令牌：

```bash
ANALYTICS_ADMIN_TOKEN=local-development-token-only npm run analytics:dev
```

服务只监听 `127.0.0.1:4318`。将 `.env.example` 复制为 `.env`，配置 `EXPO_PUBLIC_ANALYTICS_URL` 为 iOS 的 `http://127.0.0.1:4318` 或 Android 模拟器的 `http://10.0.2.2:4318`，重启 Metro，再在 App 设置里自愿开启。服务端令牌不要写成 `EXPO_PUBLIC_` 变量。

```bash
export ANALYTICS_ADMIN_TOKEN=local-development-token-only
curl -H "Authorization: Bearer $ANALYTICS_ADMIN_TOKEN" http://127.0.0.1:4318/stats
```

返回 Asia/Shanghai 时区的日/月活跃安装数、页面 UV/PV 和导入结果数量。数据只代表同意统计的安装，不等于准确人数。客户端只接收固定字段，队列最多 200 条、保留 7 天；撤回后中止请求、清队列和安装标识。服务器拒绝额外字段、事件去重并保护统计查询。尚无正式 HTTPS 部署、可视化管理页面及 30/90 天回访报表。

## 复现原生 OCR 测试

测试资料在 `private-fixtures/ocr/report-a.pdf`、`report-b.pdf`，人工核对结果为同目录 `expected.json`。这些文件不会进入正式 App。

- iOS：用 CocoaPods 自带的 Ruby 执行 `scripts/prepare-ios-ocr-tests.rb`，生成 `tmp/ocr/ios-tests/LocalOCRTests.xcodeproj`；以 `xcodebuild test` 在指定模拟器运行 `LocalOCRTests`。结果 JSON 保存在 `.xcresult` 附件，导出到私有目录后命名为 `ios-simulator-a.json`、`ios-simulator-b.json`。局部补读测试的 `ocr-ios-cells` 附件另存为 `ios-simulator-a-cells.json`。
- Android：在 `android/` 中执行 `./gradlew :local-pdf:connectedDebugAndroidTest -PreactNativeArchitectures=arm64-v8a`。测试 APK 才会包含私有样本；需要保留输出时手动安装 test APK 并运行 instrumentation，结果在测试包 `expo.modules.localpdf.test` 的 `files/ocr-a.json`、`ocr-b.json`。局部补读结果 `files/ocr-cells.json` 另存到私有目录的 `android-a-cells.json`。本次在模拟器飞行模式下通过。
- 比较字段：`node scripts/check-private-ocr.mjs` 编译当前解析器，读取整页输出及可选的 `*-a-cells.json`，对两端真实输出逐项比较项目、结果、单位、参考范围、姓名和日期。局部输出应来自 App 自动定位的区域；手选测试区域仅作为对照。缺失或不一致必须被明确标记，否则命令失败。它会报告完整匹配数量，不能将“所有差异已标记”读作“全部字段正确”。

Jest 测试不依赖私有样本；另有 iOS XCTest、Android instrumentation 和两端 Maestro 流程。本次明细见 `docs/实施记录.md`。
