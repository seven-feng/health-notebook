# 个人健康记录 App · 产品方案 v0.2

更新日期：2026 年 10 月 23 日  
状态：产品基线。本次依据两份真实 PDF 补充决策：将 PDF 页面的本地 OCR 提前至首版，现已加入拍照和相册导入；执行细节及已测边界以技术方案和实施记录为准。

## 1. 本次调整

产品继续帮助用户整理自己和家人的就诊资料，查看指标历次变化。首版重点收敛到“把浙一常见报告可靠地变成可查记录”。

| 调整项       | v0.2 的处理                                                                                   |
| ------------ | --------------------------------------------------------------------------------------------- |
| 识别能力     | 将“能读取 PDF”与“能准确提取指标”分开验证；先支持验证通过的文字版 PDF 模板                     |
| 扫描页与图片 | 拍照、相册选图以及扫描版或混合 PDF 使用本地 OCR；仅已验证的版式自动整理指标，不支持部分可归档 |
| 账号定位     | 本地优先、账号按需启用；首次导入不强制注册，登录不默认上传病历                                |
| 免费范围     | 建议核心流程免费：受支持报告提取、核对、时间线、趋势、原件查看、个人资料导出与备份            |
| 竞争策略     | 同类产品已存在；将“免费且省事”作为待验证的竞争假设，不把本地保存或趋势图当作独有功能          |
| 使用统计     | 经适用的告知与同意收集最少事件，独立于病历数据；不再承诺整个 App 完全不联网                   |
| 开发顺序     | 先做真实 PDF 的技术与体验验证，再投入完整 App；验证失败时明确缩小支持范围                     |

## 2. 用户、定位与首版范围

**定位：本地优先的个人健康记录 App，免费整理支持的报告，查看历次指标变化。**

首批用户是有重复检查、复诊需求，愿意自行导入本人资料的人。以浙一常见数值检验报告切入，同时支持 iOS 和 Android；两个系统分别验证。

用户主要解决三个问题：什么时候检查过、原报告在哪里、这个指标上次是多少。保留就诊事件的手动补充和资料关联能力，使记录能持续积累。账号将来承载必要的用户权益和可选服务，不作为核心本地流程的入口门槛。

| 首版包含                                                   | 后续按证据决定                   |
| ---------------------------------------------------------- | -------------------------------- |
| 系统文件导入，以及实测可用的支付宝“其他应用打开”           | 其他医院和更多 PDF 模板          |
| 已验证模板的本地文字提取、PDF 本地 OCR 与字段整理          | 更多报告版式                     |
| 拍照与相册单张导入、裁剪旋转、原件保存、核对更正、重复提示 | 批量图片、多页合并、自动透视校正 |
| 按成员独立的报告时间线、就诊事件、指标表与趋势             | 跨设备同步、协作                 |
| 删除、加密备份与恢复、最少使用统计                         | 具体账号权益和付费套餐           |

疾病判断、疗效评价、诊断与用药建议不属于产品范围。趋势只描述事实，例如“100 → 80，较上次减少 20”。

### 2.1 本机多成员（2026-10-23 确认方案）

- 每次启动默认进入“我”。在记录、指标、设置页右上角切换成员，保留当前标签页；下方只显示该成员的报告、待核对项、就诊和指标。
- 成员弹层可添加家人，称呼必填，报告姓名和出生日期选填；设置页可编辑当前成员资料。无需注册账号。
- 导入 PDF、拍照、相册和外部“其他应用打开”归入接收时选定的成员。正在处理的任务不因之后切换成员而改变归属；冷启动默认归入“我”。
- 不设全家的待分配报告中心。暂存仍在当前成员时间线；姓名冲突需要明确核对，不自动推荐或切换到其他成员。
- 详情与核对沿用现有的原件片段、手势放大、指标编辑和分组流程。不同成员即使同名也不会合并趋势，就诊仅能关联自己的报告。
- 升级后已有资料保留，统一放入“我”。本轮不提供已归档报告跨成员移动或成员删除。

## 3. 报告识别：先验证，再承诺

PDF 不一定有可用文字层；拍照和相册图片则需要 OCR。即使文字可以复制，表格行列、项目与数值对应关系也仍需验证。

| 检查结果                       | 处理方式                                                                                                        |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| 有可用文字及位置，模板已验证   | 本地读取文字和坐标，按布局与规则整理字段，进入核对页面                                                          |
| 有文字但布局未支持、乱码或错序 | 保留原件，明确“暂不支持自动提取”；允许手动补录，不生成猜测字段                                                  |
| 扫描版或混合 PDF               | 按页选择本地 OCR，已验证模板自动整理字段；未支持页或不确定字段明确标记，用户可核对、归档或补录                  |
| 拍照或相册图片                 | 用户先裁剪、旋转并明确开始识别；本地 OCR 和模板规则提取候选，照片指标核对后保存；未知模板可查看原图、补录或归档 |
| 损坏、受保护或无法打开         | 显示可理解的原因，支持取消并重新导入可读取的文件                                                                |

可在桌面验证阶段使用 PyMuPDF、pdfplumber 等工具测试可提取性；移动端需要根据系统能力、库许可、打包方式和性能另行选型。桌面解析成功不等于已经完成手机端适配。

OCR 解决图片转文字，字段解析还需确定项目、结果、单位、参考范围及日期的对应关系。LLM 也可能出错；不预先承诺它一定必要或一定不需要。

首版优先走无需云端模型的路径。若本地规则无法稳定覆盖目标报告，先调整模板范围或继续验证本地 OCR；若以后考虑云端模型，应作为单独产品决策，同时重新评估成本、告知授权和数据流，不能作为静默后备方案。

## 4. 核心体验

**支付宝或文件应用 → 导入 PDF → 检查支持情况 → 本地处理 → 核对保存 → 时间线／指标趋势。**

新增入口：**记录 → 拍照识别／从相册选择 → 裁剪、旋转 → 开始识别 → 核对保存。** 一次一张，保留报告名称、姓名、日期及完整指标。只在选择拍照时请求相机权限；拒绝后可前往设置或改用相册。取消选择不创建记录。当前不提供自动透视矫正、清晰度判断、手写识别或多页合并。

接收文件后先复制到 App 管理的空间，避免临时链接或文件权限失效。立即显示“文件已收到”，解析耗时放在后台处理；系统中断后能恢复任务。

核对页面按原报告顺序每组展示最多 5 项，跨页或左右栏时拆组，上方展示对应原文图片。名称旁用小字显示单位，右侧显示结果及操作。正常项无需单独确认，点击“修改”可编辑；识别存疑的项目显示“待核对”，点击后查看原文和编辑。图片可点开放大，关闭保留输入与位置。

顶部只显示实际剩余疑点数量；本组有疑点时按钮定位待核对项，处理完成后显示“下一组”，不会再要求确认同组的正常项。最后一组统一“保存报告”；如果之前跳过的组还有疑点，显示“返回待核对项”。点击“本项已核对”仅处理该项，翻组、收起和查看图片不会确认或保存。修改项目后重新要求核对。日期与患者归属仍需确认。

缺失、规则冲突和格式异常的字段优先标出，但不把“没有发现疑点”等同于正确。PDF 与照片均可快速浏览后统一确认整份报告；通用核对提醒不计入逐项待核对数量，实际识别疑点需处理。暂存不清除尚未解决的提示，报告整体确认前不进入正式趋势。

保存后直接读取本地数据库，通常不再解析 PDF。重新解析需保留原值及用户修正，并让用户确认差异；点选任何指标结果，都能打开对应原文页。

主要页面为“记录”“指标”“导入核对”“报告详情”和“设置”。设置内提供备份、恢复、删除、使用统计开关；账号入口随具体服务需要上线。

时间线区分报告日期、采样日期和就诊日期。缺失日期不以导入时间冒充；手动添加的就诊事件可关联多份报告，同一天的报告不自动认定为同一次就诊。

## 5. 比较与数据质量规则

| 情况                                       | 展示规则                                                                   |
| ------------------------------------------ | -------------------------------------------------------------------------- |
| 项目定义、单位及必要上下文可比             | 展示原值、测量日期和差值；可用趋势图                                       |
| 仅名称相同，单位、标本或方法不同／无法确认 | 分开展示或提示可比性未确认，不直接合并；单位换算和名称映射只用验证过的规则 |
| 各次参考范围不同                           | 每条结果保留自身范围；不套用统一正常区间解释全部历史值                     |
| 原报告有高低标记                           | 照实展示并标明来源，不生成健康分数或病情结论                               |
| “<5”“>100”“阴性”等                         | 保留运算符或定性文字，不当作精确数值参与差值计算                           |
| 同一成员重复导入同一文件                   | 用文件指纹提示打开已有记录；不同成员分别保存                               |
| 不同文件疑似相同报告                       | 提示核对，未经确认不合并或删除                                             |
| 报告姓名与当前成员不一致                   | 保留在当前成员档案，提示对照原件确认；不自动换人，未确认结果不进入趋势     |

本地保存原 PDF 或用户确认裁剪后的报告图片、报告字段、指标原始表达、可用数值、单位与范围、日期含义、原文页码、解析版本、确认状态和修正记录。删除后同时更新关联事件、搜索索引及趋势，避免出现已删报告的残留指标。

照片原件保存的是用户确认后的裁剪内容，不修改相册中的原图；支持手势放大查看，导出为单页 PDF。重复检测针对同一处理后图片，不会把两次拍照自动当作同一份报告。

## 6. 本地资料、账号与使用统计

| 数据／功能                      | 处理原则                                                           |
| ------------------------------- | ------------------------------------------------------------------ |
| 病历、PDF、照片、指标及解析过程 | 设备本地处理与存储；不进入遥测、网络日志或崩溃上报                 |
| 账号与会员权益（启用后）        | 与本地病历库分离；登录、退出和账号切换不自动上传或归属变更本机病历 |
| 使用统计                        | 取得适用同意后上报最少事件；支持关闭，不影响核心功能               |
| 备份与迁移                      | 用户主动导出加密文件；备份同时包含原件与结构化数据，恢复后校验关联 |

核查系统自动云备份与第三方 SDK，确保宣传与实际行为一致。用户主动把备份存到云盘时应清楚知道目的地；账号存在并不代表已提供云端病历备份。

统计事件限定为 App 打开、页面浏览、导入开始／成功／失败、耗时档位等。属性采用固定代码，不传医院、报告名称、文件名、病种、指标项目与数值、备注、原文、报告哈希或完整错误堆栈。统计也不上传本机病历的历史日期。

无需注册时，使用随机安装标识衡量活跃安装数；它不等于真实人数，重装、换机和多设备会影响去重，也不因此成为完全匿名数据。拒绝统计的用户不计入上报样本，不能把样本月活称为全部用户月活。主动反馈按另行明确授权处理，不能默认附带报告。

| 指标           | 用途与口径                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------ |
| DAU／MAU       | 自然日／自然月内发生约定活跃事件的唯一安装标识数；看板标明统计时区和仅含同意统计的样本           |
| 页面 UV／PV    | 页面访问的唯一安装数／有效浏览次数；不传页面中的病历内容                                         |
| 导入成功率     | 自动提取完成的任务数／进入自动提取的任务数；受支持格式、未支持文件和中断单独计数                 |
| 核心使用完成率 | 首次导入后成功确认保存的安装占比；与“解析完成”分开看                                             |
| 回访与再次导入 | 按首次使用日期分组，观察 30／90 天回访和再次导入；结合复诊频率解释，不以每日打开作为唯一成功标准 |

App 核心功能可离线使用，账号及统计服务联网。上线前按最终实现确认适用的隐私义务；“本地优先”不能作为免除责任的承诺。

## 7. 免费策略与竞争验证

建议让用户免费完成受支持报告的导入、核对、保存和对比，也能自由查看、导出和备份自己的资料。免费范围在导入前说明；首版如设置页数或文件大小上限，应基于设备能力明示，而非处理后才要求付费。

本地处理可以减少按次云端推理成本，但仍有报告模板适配、移动端开发、测试、客服、统计服务和分发维护成本。免费能否持续需按真实支持成本判断，不预设“没有成本”。

已知同类产品包含病历管家、医路记、LabLine。病历管家公开列有 PDF 识别、时间线、指标对比与本地存储；因此这些功能不足以构成独有优势。用户反馈其 PDF 识别存在付费门槛，可作为本次竞争假设的依据，但免费额度、具体套餐及用户提到的豆包 API 使用情况尚未独立验证。

竞争验证使用同一批脱敏报告，比较导入步骤、正确率、必须修改的字段、从导入到获得趋势的时间、离线可用性、数据导出和收费限制。免费需要和准确、省事同时成立。

后续收费候选是明确有需求的同步、协作等服务；账号可用于必要权益。首版不急于确定套餐，不将取回用户自己的原始资料设为付费障碍。

## 8. 实施顺序与验收门槛

**A. 报告与入口验证。** 收集经授权且保留 PDF 原有结构的样本，建议先覆盖 20–30 份、多个日期和至少两种实际模板；先检查样本是否包含不同人员、日期和单位。准备人工核对数据，并留出未参与规则开发的报告验证泛化。不能把同一模板少量成功样本称为全院支持。

**B. 单平台端到端原型。** 验证支付宝实际传递内容和系统文件导入，完成本地解析、核对保存、两次结果对比和重启读取。测量首发设备上的耗时与内存；若直接分享不通，使用明确可用的文件导入流程。

**C. 小范围试用。** 加入去重、纠错、任务恢复、删除、备份恢复和最少统计。首批建议邀请 5–10 位有重复检查需求的用户，在其本人设备上观察体验，研究人员不默认取得病历。

建议的验收条件：

- 对外宣布支持的模板，在留出样本上按“项目＋结果＋单位＋日期＋参考范围”整条核对；关键数值与归属不能有未经发现的错误。无法确定的行进入待核对，不静默丢弃。
- 初步统计提取覆盖率、完整记录正确率和每份报告的更正负担；不能只报告 OCR 字符准确率。验收样本全部通过也不代表未来报告零错误。
- 导入后 1 秒内有明确反馈；结构化结果保存后查看无需重新识别。具体解析速度根据真实设备、页数和模板测试后定标。
- 飞行模式可完成核心流程；删除、重复导入、修改后的趋势与原件一致；备份恢复可还原文件及关系；检查网络请求中无病历字段。
- 使用统计拒绝／撤回后停止事件上传并清理待发送队列；统计服务失败不影响本地功能。

## 9. 当前决策点

已确认两份实际浙一 PDF 没有可用文字层，本地 OCR 加对应版式规则能自动整理大部分字段。下一步重点是更多独立样本的识别效果、用户核对负担、真机接收文件的体验，以及用户是否觉得免费方案足够省事。当前适配与测试结果见实施记录。

若目标样本的本地解析可靠，就推进免费核心版；若只能覆盖部分格式，就明确支持范围并继续收集验证样本；若关键格式必须依赖云端模型才能满足需求，应先重新讨论成本和隐私定位，再扩展功能。

本次已产出两份原始 PDF 的字段核对结果、模板范围和两端模拟器实现；后续继续用未参与适配的原始 PDF 验证，并完成真机入口与性能测试。
