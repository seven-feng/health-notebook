# 单项检验报告识别修复

## 复现与原因

用户提供一张只有一项指标、带“检测方法”列的检验报告照片。附件方向横置，但用户在导入时已旋转；手机原件尺寸和 OCR 坐标确认它已转正。因此，本次实际失败与用户的旋转操作无关，也没有新增自动旋转功能。

使用手机已有原件重新执行本地 OCR，文字、数值和采集日期均可读到，但解析结果为零项。原因是：

1. 通用表格至少要求三行有效数值／参考范围证据；这个版式没有适配的专用模板，又不满足带近邻分区标题的解析规则。
2. 未识别“检测方法”列，最后的单位列延伸到页边，方法文字被混入单位。
3. OCR 把独立箭头读成了“1”，它落在参考范围列边缘；直接拼接会改变参考范围下限。单位末尾还多出一个点。

## 修改

- 通用表格仍校验项目、结果、单位、参考范围列的位置。只有一至两项时，额外要求明确检验／检测报告标题、患者姓名、有效采集日期、每项完整的数值／参考范围证据；匿名碎片、无结果的参考表和科普示例不因此放行。
- 单独识别方法列，支持“参考范園”这一 OCR 字形，保持单位边界；没有用医院名称或具体指标／数值硬编码适配。通用结果不继承专用模板的指标代码、样本或方法条件。
- 参考范围按字间距识别分开的片段，独立标记不拼进下限；不明确标记继续要求核对，两段有效范围不擅自择一。明确的箭头保留，读成“1”的箭头不反推为升高或降低。
- 去掉紧连中文项目名前的序号。已知单位后多出的点可规范化，但保留原始单位并要求核对；其他未知单位继续保留。

## 验证与生效

- `npm run verify`：39 套／495 项 Jest、类型检查、lint、1 项统计 HTTP 测试通过。新增 11 个合成场景覆盖单项／双项、方法列、姓名／日期／表头等证据不足、分离标记、两个范围、单位尾点和数值零。
- 旧专用模板的拒绝规则仍用专用解析器断言；符合新规则的表格可走通用回退，另断言必须核对且不产生专用指标代码。这是支持短表后的预期行为变化。
- 本机私有夹内 18 份有效 OCR 布局（325 项结果）用修改前后解析器比较，完整结果一致。这里是缓存解析回归，不是重新跑过 18 份原生 OCR。
- 完整重新加载 iPhone 开发版、恢复原成员和报告，使用已有“重新识别原报告”操作生成候选。手机核对页实际出现一项，名称／数值／单位／参考范围／采集日期与原件一致；保留箭头和单位等核对提示。
- 前后读取持久报告与原件记录，内容一致；候选尚未替用户确认保存。临时调试已清理。未专项验收 Android 原生 OCR；本次未改 Swift／Kotlin，无须重装原生包。

检查日志和无医疗数值的摘要在 `tmp/single-lab-report-20261026/`。原始照片、原生提取与手机候选仅保存在忽略目录 `private-fixtures/single-lab-20261026/`；自动测试只包含合成数据。

## 单位大小写补充修复

后续手机上的另一份识别结果是 `ng/ml-`，原始单位字段同样是 `ng/ml-`。此前验证的缓存为 `ng/mL.`，不能代表这次识别。代码没有将大写 L 转为小写，但缺少这种等价写法的规范化，也未处理单位末尾的横杠。

- 对明确支持的浓度单位，仅将升的小写 `l` 规范为 `L`（如 `ng/ml` → `ng/mL`），保持其他前缀的大小写和数值不变；通用表格、分区表格、浙一模板和指标匹配复用该规则。未知单位不猜测，`ng/L` 与 `ng/mL` 不合并。
- 通用表格末尾多出的一个点或横杠，仅在移除后是已知单位时整理；保留 `originalUnit` 和单位核对提示。大小写规范化本身不新增警告。
- `npm run verify`：39 套／509 项 Jest、类型检查、lint、1 项统计 HTTP 测试通过。新增 14 个合成场景覆盖大小写、前缀区分、不同体积单位和尾部噪声。
- 重新读取手机当前原件，用本机与手机运行中的解析器均得到 `ng/mL`，原始字段仍为 `ng/ml-`，数值未变。持久记录前后完全一致；未触发页面重新识别、保存或完整重载。已有记录需通过“重新识别原报告”生成新候选，再由用户核对保存。
