# 健康小本 · health-notebook

用 React Native、TypeScript 和 Expo 开发的 iOS／Android 本地健康记录 App。免费导入 PDF 或单张报告照片，对照原件核对，整理本人及家人的记录，查看可比较指标的历史变化。

品牌名称为“健康小本”，采用书页与爱心结合的 Logo。名称、图标与原生工程已同步，资源位于 `assets/brand/`；桌面名称和图标需重新构建安装后生效。

**当前是可运行、已在 iPhone 体验的验证版，尚未发布到应用商店。** 无账号、付费 AI、云端 OCR 或完整备份恢复。产品与技术文档于 2026-10-25 对照源码和已有验证记录同步；各轮验证范围见对应记录，文档同步不代表重新完成原生构建或真机验收。

## 当前核心能力

- 本地 PDF 文字提取与 OCR；拍照／相册单张导入、裁剪和旋转。
- 浙一适配与通用表格；多页检查分区、跨页表格、小表和文字结果；未整理内容保留原件入口。
- 按原件分组、在列表直接勾选疑点，编辑、暂存、保存；原图可放大查看。
- 按成员隔离的“就诊记录／检查报告”视图、打印门诊病历／超声报告原文整理与检验关联、原件导出及可比指标变化。
- 已确认就诊以连续病历阅读，备注和关联检验可单独编辑；体格检查统一标点、间距与分段，编辑值及原始识别内容保留。
- 检验报告重新识别先生成候选，保留用户修正；已知模板的缺失日期补齐。就诊记录尚无主动重新识别入口。
- iPhone 微信“其他应用打开”已修复并由用户确认恢复导入。

已实现不表示任意报告都能准确识别。40 页开发报告可整理 7 分区／115 项，仍漏读 4 个图形箭头；严格验收与更多独立样本仍待补齐。通用新格式也不自动建立跨医院趋势。详见[状态与限制](docs/当前状态与待办.md)。

## 日常运行

首次下载并安装依赖：

```sh
git clone https://github.com/seven-feng/health-notebook.git
cd health-notebook
nvm use
npm ci
```

首次运行需安装原生开发包，按目标平台选择一个命令（iOS 需要 macOS 和 Xcode；Android 需要 Android SDK 和 JDK 17）：

```sh
npm run ios -- --configuration Debug
# 或
npm run android -- --variant debug
```

`ios/`、`android/` 是本机生成的工程，首次构建由 Expo 生成；自定义原生模块源码在 `modules/local-pdf/`，配置在 `app.config.ts` 和 `plugins/`。真机安装需配置自己的开发者签名。

开发包安装后，日常启动开发服务：

```sh
cd health-notebook
nvm use
npm start
```

默认使用已安装的 **Debug Development Build**。停止开发服务，在其终端按 `Ctrl+C`。原生模块变化需重新编译安装；Expo Go 不能运行本项目。

Release 用于明确需要脱离电脑的体验。Xcode 切换配置只影响下一次构建，重新安装后才改变手机上的版本。具体操作见[开发与测试](docs/本地开发与测试.md)。

## 资料与验证

原件和结果存本机，数据库使用 SQLCipher。完整备份与恢复尚未实现，请保留医院原始文件。使用统计默认关闭，未正式部署；Android ML Kit 自身诊断活动另见[依赖记录](docs/third-party.md)。

日常代码检查为 `npm run verify`；原生及 E2E 按改动选择执行。测试数据只用于专用模拟器，真实样本与完整输出放在忽略的私有目录，不把历史构建成功当作当前全面验收。

各轮自动检查和设备验证范围见[当前状态与待办](docs/当前状态与待办.md)，历史测试结果不代表所有设备和报告格式均已通过验收。

仓库保留应用源码、产品／技术文档、浏览器原型与合成测试资料。真实报告、识别输出、数据库、密钥、签名材料、编译产物及本地设计／调试截图不上传。文档中的 `tmp/`、`private-fixtures/`、设计稿和截图路径是本机验证证据，克隆仓库不包含这些文件。
